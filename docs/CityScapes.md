python -m pip install cityscapesscripts

# Дополнительные данные: train_extra (грубая разметка)

Кроме 2975 точно размеченных кадров у Cityscapes есть **19998 кадров
train_extra** с грубой разметкой. Это в 6.7 раза больше сцен — и единственный
способ дать модели больше данных, не меняя домен.

```
csDownload -d data/raw/cityscapes leftImg8bit_trainextra.zip gtCoarse.zip
```

`leftImg8bit_trainextra.zip` — 44 ГБ, `gtCoarse.zip` — ещё ~1.3 ГБ; без
второго кадры бесполезны, разметки к ним не будет. Кадр
`troisdorf_000000_000073_leftImg8bit.png` в архиве битый (полностью чёрный) —
датасет выбрасывает его сам, качать заново не нужно.

## Чем грубая разметка отличается от точной

Полигоны обведены «внутри» объектов, между соседними объектами остаются
широкие полосы `ignore`. Границы по ней выучить нельзя — а именно на границах
компактные модели и теряют mIoU. Поэтому грубые данные годятся для
**предобучения**, а не вместо точных.

## Порядок этапов

Тот же, что у самих авторов Cityscapes и у лидербордных решений: **сначала
грубые, потом точные**.

```bash
# 1) предобучение: train + train_extra с gtCoarse, ~1/3 обычного числа эпох
python scripts/train.py experiment=<ваш эксперимент> \
    data/dataset=cityscapes_seg_extra trainer.epochs=50

# 2) дообучение: только gtFine, lr в 3-10 раз меньше
python scripts/train.py experiment=<ваш эксперимент> \
    model.student.checkpoint_path=outputs/<...>/best.pt \
    optimizer.lr=1e-4
```

Обратный порядок (сначала точная разметка, потом грубая) хуже: последними
модель видит именно грубые границы и запоминает их.

На грубой разметке стоит включить `cat_max_ratio` (он есть в
`cityscapes_seg_strong_transform*`): полосы `ignore` там широкие, и кроп,
целиком попавший в неразмеченное, дал бы CE по пустому множеству пикселей,
то есть NaN. С `cat_max_ratio` такой кроп перевыбирается.

Валидация в обоих случаях одна и та же — `val` с `gtFine`
(`val_annotations: gtFine` в конфиге датасета), иначе mIoU перестанет быть
сравнимым с прошлыми прогонами и с публичными числами.

## Что это даёт дистилляции

Отдельно полезный сценарий: на train_extra у нас есть сильный учитель и
19998 новых кадров, а точность их разметки для дистилляционных членов
(KD по логитам, CWD, hint) не важна вовсе — они считаются по предсказаниям
учителя, а не по меткам. Грубые метки при этом продолжают работать в CE
там, где они есть. То есть этап 1 — это ещё и способ выучить на учителе
в 7 раз больше сцен.

Эпоха на train+train_extra примерно в 7.7 раза длиннее, это стоит заложить
в число эпох.
