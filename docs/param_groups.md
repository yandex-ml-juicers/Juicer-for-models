# Группы параметров: раздельные lr и weight decay

Один общий learning rate на всю модель — неявное допущение, что все её
части находятся в одинаковых начальных условиях. Для сегментатора с
предобученным энкодером это не так.

## Зачем

**Энкодер против декодера.** У `timm_unet` с `pretrained: true` энкодер
приходит с ImageNet и уже умеет извлекать признаки, а декодер и голова
инициализированы случайно. При общем `lr=1e-3` первые же эпохи затирают
предобучение: градиент от случайной головы течёт назад и разрушает то, за
что вы платили. Канонический приём — дать энкодеру долю общего lr, обычно
`0.1`.

**Weight decay на нормализациях.** AdamW с `weight_decay: 3.0e-2` (значение
из конфигов проекта) применяется в том числе к `gamma`/`beta` BatchNorm и к
bias свёрток. Decay на `gamma` — это систематическое подавление масштаба
нормализации, чего никто не хотел. Стандарт везде — исключать из decay всё
одномерное.

**Параметры лосса.** Адаптеры FitNets и проекторы HeteroAKD живут внутри
`criterion` и попадают в optimizer вместе с учеником. Это часть целевой
функции, а не модели, и по умолчанию они идут без decay.

## Как включить

```yaml
optimizer:
  lr: 1.0e-3
  weight_decay: 3.0e-2

param_groups:
  encoder_lr_mult: 0.1              # энкодеру 1.0e-4 вместо 1.0e-3
  no_decay_on_norm_and_bias: true
```

`param_groups: null` (значение по умолчанию) — прежнее поведение, одна
группа на всё. Ничего в существующих конфигах не меняется.

Из CLI:

```bash
python scripts/train.py experiment=<...> 'param_groups={encoder_lr_mult: 0.1}'
python scripts/train.py experiment=<...> ~param_groups     # выключить
```

## Все рычаги

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `encoder_lr_mult` | `1.0` | Множитель `optimizer.lr` для энкодера |
| `encoder_weight_decay` | `null` | Свой wd энкодеру; `null` — как у остальных |
| `criterion_lr_mult` | `1.0` | Множитель lr для обучаемых частей лосса |
| `criterion_weight_decay` | `0.0` | wd для адаптеров/проекторов лосса |
| `no_decay_on_norm_and_bias` | `true` | Выносить одномерные параметры в группы с `weight_decay=0` |
| `encoder_prefixes` | `null` | Префиксы имён параметров вручную |

Все `*_mult` — **множители** от `optimizer.lr` и `optimizer.weight_decay`,
а не абсолютные значения. Так перебор lr (свипы, CLI-override) не ломает
соотношение между частями модели.

## Что считается энкодером

Таблица в `src/training/param_groups.py`:

| Модель | Префиксы параметров |
|---|---|
| `TimmUNet` | `encoder.` |
| `UNet` | `encoders.`, `bottleneck.` |
| `SegNeXt` | `encoder.` |
| `SegFormer` | `model.segformer.` |

У `UNet` боттлнек отнесён к энкодеру: он завершает нисходящий путь, а в
timm-версии физически является последней стадией бэкбона.

Для модели не из таблицы задайте `encoder_prefixes` вручную. Если этого не
сделать, а `encoder_lr_mult` при этом отличается от `1.0`, запуск **упадёт
на старте** — молча применить общий lr нельзя: прогон выглядел бы
настроенным, а был бы обычным.

## Как проверить, что рычаг применился

В `train.log` печатается таблица групп:

```
группа                тензоров    параметров          lr  weight_decay
decoder                      9       644,848    1.00e-03          0.03
decoder_no_decay            17           787    1.00e-03             0
encoder                     80     3,546,592    1.00e-04          0.03
encoder_no_decay           128        48,796    1.00e-04             0
```

В ClearML на графике `lr` появляются отдельные серии `encoder`, `decoder`
и так далее — по ним видно, что множитель держится всё обучение, а не
только на первом шаге.

## Подводный камень: `eta_min`

`eta_min` у `CosineAnnealingLR` — **абсолютная** нижняя граница, одна на все
группы. Она обязана быть ниже самого маленького lr в `param_groups`:

```yaml
optimizer:   {lr: 1.0e-3}
param_groups: {encoder_lr_mult: 0.1}   # lr энкодера = 1.0e-4
scheduler:   {eta_min: 3.0e-4}         # ОШИБКА: больше, чем lr энкодера
```

В этом примере косинус будет не отжигать энкодер, а **разгонять** его с
`1e-4` до `3e-4` — ровно наоборот задуманному. `scripts/train.py` ловит это
на старте и пишет `WARNING`, но лучше сразу держать `eta_min` в районе
`base_lr / 100…1000`.

Оговорка помельче: поскольку `eta_min` — абсолютная добавка
(`lr = eta_min + (base_lr - eta_min) * ...`), на самом хвосте отжига обе
группы сходятся к `eta_min` и отношение lr уползает к единице. Практического
значения это не имеет: к тому моменту оба значения уже пренебрежимо малы.

## Что ожидать по метрике

По литературе и общей практике для сегментатора с предобученным энкодером:
`encoder_lr_mult` и отключение decay на нормализациях дают суммарно порядка
**+0.5…1.5 mIoU**. Это диапазон, а не обещание, — измеряйте на своём сетапе,
желательно на 2-3 seed'ах.
